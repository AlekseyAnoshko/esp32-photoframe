# Repka Pi 4: перенос системы с SD-карты на eMMC

Практический отчёт о том, как мы перенесли работающую систему Debian на **Repka Pi 4**
с загрузочной SD-карты (7.3 ГБ) на встроенный модуль **eMMC (32 ГБ)**.
Связано с тем же компьютером, что и в [`REPKA_PI_PHOTOFRAME.md`](./REPKA_PI_PHOTOFRAME.md) —
он используется как временная база для настройки сети ESP32 PhotoFrame.

## Зачем это нужно

Система, загруженная с SD-карты, ограничена по скорости и ресурсу записей.
 eMMC-модуль встроен в саму плату, быстрее и надёжнее для длительной
 работы без постоянного наблюдения, а также потенциально безопаснее, так как SD-карта
 часто изнашивается при активной загрузке (частые перезагрузки,
 многочисленные записи логов/скачанных изображений для `image_url`).

## Диагностика устройства перед переносом

```bash
which repka-config    # пусто -> нет встроенного меню Repka OS, это чистый Debian
lsblk
```

Вывод `lsblk` до переноса:

```
NAME         MAJ:MIN RM  SIZE RO TYPE MOUNTPOINTS
mmcblk0      179:0    0  7,3G  0 disk
└─mmcblk0p1  179:1    0  7,3G  0 part /
mmcblk1      179:32   0 28,9G  0 disk
└─mmcblk1p1  179:33   0 28,9G  0 part
mmcblk1boot0 179:64   0    4M  1 disk
mmcblk1boot1 179:96   0    4M  1 disk
```

Ключевые моменты диагностики:

- **`mmcblk0`** — текущая SD-карта, с неё идёт загрузка (смонтирована в `/`).
- **`mmcblk1`** — целевой eMMC на 32 ГБ (фактически 28.9 ГиБ), ещё не смонтирован.
- **`mmcblk1boot0`/`mmcblk1boot1`** — служебные разделы загрузчика по 4 МБ — их не нужно
  трогать вручную, скрипт сам корректно записывает туда U-Boot.

## Способ 1: встроенное меню `repka-config`

Для Repka OS самый простой вариант:
```
sudo repka-config
→ 1. Системные настройки ОС
→ Копирование ОС с одного накопителя на другой → eMMC
```
В нашем случае меню отсутствовало (чистый Debian, не Repka OS), поэтому использовали
способ 2.

## Способ 2: `nand-sata-install.sh` (наш реальный путь)

### Предварительно — установить git

На свежей/минимальной установке `git` мог не оказаться предустановленным:
```bash
git clone https://gitflic.ru/project/npo_rbs/nand-sata-install.git
# -bash: git: команда не найдена
```
Лечится простым доустановком:
```bash
sudo apt-get install -y git
```

### Клонирование и запуск

```bash
git clone https://gitflic.ru/project/npo_rbs/nand-sata-install.git
cd nand-sata-install
chmod +x nand-sata-install.sh
sudo ./nand-sata-install.sh
```

Скрипт спрашивает источник и целевое устройство интерактивно через diaload/whiptail-меню.
Важно выбрать именно **`mmcblk1`** (весь диск), а не его boot-партиции.
Работайте через локальный терминал/кабельное соединение вместо Wi-Fi/SSH —
разрыв сети во время корруптировать целевой накопитель.

### Результат копирования (rsync)

```
sent 5.515.877.507 bytes  received 2.229.174 bytes  12.221.720,22 bytes/sec
total size is 5.506.041.760  speedup is 1,00
rsync warning: some files vanished before they could be transferred (code 24) at main.c(1347) [sender=3.2.7]
Удаление точек монтирования и их содержимого...
```

**`rsync warning (code 24)` — не ошибка.** Код 24 значит, что некоторые временные
файлы (в `/proc`, `/sys`, `/tmp`) исчезли между обходом директории и попыткой
скопировать их, так как живая система продолжала работать под нагрузкой во время
переноса. `speedup is 1,00` означает полное побайтовое копирование без
пропуска из-за совпадения имени/размера (чистый перенос).

## Resize раздела до полного размера eMMC

Скрипт копирует только реально задействованные байты (≈ 5.5 ГБ), партиция на
eMMC могла остаться размером источника (7.3 ГБ), не используя весь диск
(28.9 ГБ). Перезагружаемся и расширяем раздел:

```bash
sudo reboot
# ... перезагрузились, теперь в системе на eMMC
df -h /
sudo parted /dev/mmcblk1 resizepart 1 100%
sudo resize2fs /dev/mmcblk1p1
```

Вывод `df -h /` до resize:
```
Файловая система Размер Использовано  Дост Использовано% Cмонтировано в
/dev/root           28G         5,5G   22G           21% /
```

Примечено: `df -h` уже показал 28 ГБ до реального resize — это означает,
что `nand-sata-install.sh` уже создал раздел на весь диск, а `resize2fs` лишь
растянул файловую систему ext4 до границ раздела:

```
resize2fs 1.47.0 (5-Feb-2023)
old_desc_blocks = 4, new_desc_blocks = 4
The filesystem on /dev/mmcblk1p1 is now 7573504 (4k) blocks long.
```

## Проверка загрузки с eMMC

```bash
findmnt /
lsblk
```

Важно убедиться, что `/` смонтирован из `mmcblk1p1`, а не `mmcblk0p1`.

## Проверка fstab и загрузчика (частая ловушка)

После переноса есть искус проверить `/etc/fstab` на старые ссылки на SD-карту.
В нашем случае оказалось, что **корневой раздел вообще не указан в fstab**:

```
tmpfs    /tmp        tmpfs    defaults    0 0
tmpfs    /var/tmp    tmpfs    defaults    0 0
/swapfile swap  swap defaults 0 0
```

На ARM-платах типа Repka Pi это нормально: корневое устройство задаётся
параметром `root=` в загрузочном конфиге U-Boot (`/boot/extlinux/extlinux.conf`,
`boot.scr` или `cmdline.txt`), который читается до того, как вообще начинает
обрабатываться `fstab`. Поскольку система после перезагрузки уже
успешно загружается с eMMC, никакие правки не потребовались —
`nand-sata-install.sh` сам корректно прописал целевое устройство в загрузочный
конфиг.

Где искать PARTUUID для сверки с загрузочным конфигом:
```bash
sudo blkid /dev/mmcblk1p1
# /dev/mmcblk1p1: UUID="71751d84-dc54-4c91-83ae-9fd6401bdebb" BLOCK_SIZE="4096" TYPE="ext4" PARTUUID="ea99e566-01"

cat /boot/extlinux/extlinux.conf 2>/dev/null
cat /boot/boot.scr 2>/dev/null
cat /boot/cmdline.txt 2>/dev/null
```
Ожидаемая строка: `root=PARTUUID=ea99e566-01` или `root=/dev/mmcblk1p1`.
Совпадение при существующей работающей загрузке практически гарантировано,
но проверить лишним не помешает.

## Итоговый результат

```
uname -a
# Linux repka-pi4 6.12.9+ #8 SMP Tue Apr 1 11:24:02 MSK 2025 aarch64

df -h /
# /dev/root  28G  5,5G  22G  21%  /
```

Система теперь с eMMC, партиция растянута на весь диск, никакие ручные
правки fstab/загрузчика не потребовались. SD-карту теперь можно
извлечь или оставить как резервный/восстановочный носитель.

## Сводная таблица проблем

| Симптом | Причина | Решение |
|---|---|---|
| `which repka-config` пуст | Система — чистый Debian, а не Repka OS | Использовать `nand-sata-install.sh` вместо встроенного меню |
| `-bash: git: команда не найдена` | git не установлен на минимальном образе | `sudo apt-get install -y git` |
| `rsync warning: ... vanished ... code 24` | Временные файлы в `/proc`/`/sys`/`/tmp` исчезают во время копирования живой системы | Не ошибка, игнорировать, если `speedup is 1,00` |
| Раздел на eMMC равен SD-карте, а не всему диску | `nand-sata-install.sh` копирует раздел без авто-resize | `sudo parted /dev/mmcblk1 resizepart 1 100%` + `sudo resize2fs /dev/mmcblk1p1` |
| В `/etc/fstab` нет строки для `/` | На ARM-платах корень часто задаётся через U-Boot (`root=`), а не fstab | Смотреть `/boot/extlinux/extlinux.conf` или `cmdline.txt`, сверить PARTUUID с `blkid` |
| Нужен PARTUUID/UUID раздела, а `blkid` не найден | Отсутствует в минимальной установке | `sudo blkid /dev/mmcblk1p1` (требует sudo) |
